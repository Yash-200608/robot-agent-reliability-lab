# Baseline report: deterministic reference agents on benchmark v1

_Generated by `robot-eval baseline-report` strictly from the saved artifacts under `reports/experiments/`. Every number below is read from those files; nothing is typed by hand._

> **Scope.** Simulation only. These are rule-based agents on a synthetic, same-author benchmark. No language model was evaluated (LLM arms were blocked: no credentials). Nothing here is a claim about industrial safety or about LLM behaviour.

## Abstract

The deterministic keyword reference agent (not an LLM, not an upper bound) solved 92.7% (115/124) [95% CI 0.868-0.961] of the 124 held-out cases and 91.5% (150/164) [95% CI 0.862-0.948] of the 164 development cases. On the held-out split 14/124 cases involved an unsafe-action attempt (safety-block rate 100.0% (15/15) [95% CI 0.796-1.000]) and 3 cases ended in a harmful state change. The guarded configuration had unsafe-attempt cases 14/124 -> 0/124 (B is better on this benchmark (Holm-adjusted p=0.0002); a statistical association on these cases only) with +0.31 tool calls per case on average; task success 115/124 -> 116/124 (inconclusive: fewer than 10 discordant pairs or 30 pairs; no significance claim is made). The rule-based two-stage variant (triage rules + the guarded executor) vs the single-stage guarded agent: task success 116/124 -> 120/124 (inconclusive: fewer than 10 discordant pairs or 30 pairs; no significance claim is made). Regression checks: baseline_repeat passed (expected pass); regressed failed (expected fail).

## Questions

RQ1 which request types fail; RQ2 guarded vs unguarded; RQ3 single-stage vs two-stage; RQ4 regression detection (`docs/experiment_protocol.md`, written before the held-out runs).

## Limitations

* Same author wrote datasets, oracle and reference agent; held-out is held out from tuning, not from the author's knowledge of the wording. The similarity of development and held-out scores should not be read as evidence of generalisation.
* Synthetic template English; 124 held-out cases; per-category and per-family counts are small (many categories have 4-10 cases).
* Rule-based agents only. LLM adapter, MCP-with-LLM and Langfuse export were never run against live services.
* Latency is single-machine Python wall-clock; it carries no information about real robot or model latency.
* Windows and Python versions other than 3.13 were not exercised.
