# Architecture and dependency decisions

| # | Decision | Why | Alternatives not chosen |
|---|---|---|---|
| 1 | Build from scratch under the names `robot_eval` / `robot-eval` | The original repository was unavailable and the user asked to start from scratch; names follow the plan so a later merge is mechanical. | Waiting for the repository (blocked the whole plan). |
| 2 | pydantic v2 strict models for tool arguments and the case schema | One declarative source for validation, JSON schema (also served over MCP) and dataset schema. `strict` rejects `"1.0"` and `true` instead of coercing; `extra="forbid"` rejects unknown fields; `allow_inf_nan=False`. | dataclasses + hand validation; jsonschema. |
| 3 | Exact-arithmetic oracle (`Fraction`, squared distances) separate from the float simulator | Gives an *independent* decision procedure for boundary cases; equalities such as touching or margin-equality are decided exactly, and float/exact agreement is tested. | Re-using the simulator as its own oracle (not independent); sampling-based oracle (not exact). |
| 4 | Tool-use correctness expressed as acceptable patterns + per-argument constraints | Equivalent valid behaviours (extra pre-checks, retries) are not penalised, while forbidden actions (an unrequested move) are. | One exact expected call sequence per case (brittle). |
| 5 | Evaluator trusts only the harness-recorded trace and checks agent *claims* against the oracle | Required by the plan; prevents self-reported success. | Using the agent's own `ok` flag. |
| 6 | `unsafe attempt` computed by the exact oracle from the pose recorded before each call | Counts attempts even when the simulator blocks them, so guarding is measurable without weakening the simulator. | Counting only simulator rejections (conflates the guard with the simulator). |
| 7 | Rule-based reference agent and rule backends for the two-stage policy | Makes the pipeline, guard ablation and orchestration testable offline and deterministically. Clearly labelled as rules. | Waiting for LLM access; presenting rule results as LLM findings (rejected). |
| 8 | Wilson intervals, exact McNemar, seeded paired bootstrap, Holm - implemented with numpy + stdlib | Matches paired binary outcomes and skewed latencies; no scipy/pandas dependency on a student PC. | scipy.stats (heavier install); t-tests (wrong for paired binary). |
| 9 | Low-level `mcp.server.lowlevel.Server` for MCP, optional extra `mcp>=2.3,<3` | mcp 2.x removed `FastMCP` (renamed `MCPServer`, whose tool schemas come from Python signatures and would coerce arguments before the strict validator). Low-level handlers publish exactly the pydantic schemas and keep one validation point. | `MCPServer` with typed signatures (double validation, different coercion rules); `mcp<2` pin (old API). |
| 10 | Anthropic Messages API as the single first LLM provider (extra `llm`, lazy import) | One working provider first, as the plan asks. Official SDK, typed exceptions, `tool_use` blocks. Model id supplied by the operator (no hard-coded default that could spend money). | OpenAI/others (not first pass); LangChain-style frameworks (extra dependency without need). |
| 11 | No `temperature`/`top_p`/`top_k` and no forced `tool_choice`; final answer through a `submit_result` tool | Current API versions reject sampling parameters and newer models reject forced tool choice; a result tool keeps structure without either. | Parsing free text (fragile); forced tool choice (400 on newer models). |
| 12 | Provider refusals/timeouts become `status=error`, never a refusal or answer | A safety-classifier refusal is not an agent decision; crediting it would inflate safe-refusal scores. | Mapping refusal to `refused`. |
| 13 | Langfuse export is post-hoc per case, opt-in, behind an exporter interface | Remote tracing can never break or slow the local run; the payload is controlled and excludes labels. | Decorator-based auto-instrumentation (hidden payloads, hard to keep offline). |
| 14 | Run records are strict JSON (`NaN`/`Infinity` encoded as strings, `allow_nan=False`) | Found by a reproducibility test: NaN arguments broke equality and produced non-standard JSON. | Default `json.dumps` (emits bare `NaN`). |
| 15 | Append-only held-out access log written by the runner | Makes held-out discipline auditable and any deviation visible. | Honour system. |
| 16 | `docs/tools.md` generated from the live simulator with a staleness test | Documentation cannot drift from behaviour. | Hand-written examples. |
| 17 | `requires-python >= 3.11`, tested on 3.13 only | `StrEnum`, `datetime.UTC` need 3.11; other versions were not available to test. | Claiming 3.11/3.12 support without testing. |
